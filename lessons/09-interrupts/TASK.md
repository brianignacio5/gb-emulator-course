# Task — Lesson 09

1. `request(bit)` sets that bit in `ifFlag`. `pending()` returns the lowest set bit of `ie & ifFlag & 0x1f` as `{ bit, vector }`, or `null`. Vectors are `0x40`, `0x48`, `0x50`, `0x58`, `0x60` for bits 0–4. It does not look at `IME` and does not clear `IF`. With `IE` equal to `0x1F`, VBlank wins over Timer. `acknowledge(bit)` clears that one `IF` bit and leaves the others set. `getIe`, `setIe`, `getIf`, and `setIf` are already done.
2. Service in `Cpu.step` before `fetch8`. Apply the `EI` delay first: `imePending` sets `Cpu.ime`, then `eiDelay` becomes `imePending` so the instruction after `EI` still runs with `IME` clear. If `Cpu.ime` is set and `pending()` returns a value, clear `halt`, clear `Cpu.ime`, `acknowledge` that bit, `push16` the current `PC`, set `PC` to `vector`, and return 20. Do not fetch. Skip service when `IME` is clear or `IE` does not enable the request, and run the opcode instead. When `halt` is set, `IME` is clear, and `IE & IF & 0x1f` is nonzero, clear `halt` and fetch the next opcode. The interrupt is not taken. If `halt` is set and nothing is latched, return 4 and do not fetch. Leave the HALT bug unimplemented.
3. `DI` (`0xF3`) clears `Cpu.ime`, `eiDelay`, and `imePending`, and returns 4. `EI` (`0xFB`) sets `eiDelay` only and returns 4. `RETI` (`0xD9`) pops `PC` like `RET`, sets `Cpu.ime` immediately, and returns 16. `DI` cancels a pending `EI`. `RETI` does not wait.
4. Run `npm run test:lesson -- 09`. The test checks `pending()` returning VBlank before Timer, all five vectors taking 20 T-cycles and pushing `0x0100`, priority order with only the taken bit acknowledged, no service when `IME` is clear or `IE` is 0, `halt` cleared when an interrupt is serviced, `DI` leaving the next instruction running, `EI` delaying `IME` by one instruction, `DI` after `EI` keeping `IME` clear, and `RETI` setting `IME` so the following `step` services.
