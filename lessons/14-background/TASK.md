# Task — Lesson 14

1. `read` and `write` cover four registers. `0xFF40` is `lcdc`, `0xFF42` is `scy`, `0xFF43` is `scx`, and `0xFF47` is `bgp`. Those fields already exist on `Ppu`. `write(0xFF40, 0x91)`, `write(0xFF42, 0x10)`, `write(0xFF43, 0x20)`, and `write(0xFF47, 0xE4)` are read back as `0x91`, `0x10`, `0x20`, and `0xE4`.
2. Add a dot counter that starts at 0 and a mode that starts at 2 (OAM). `step(cycles)` returns immediately while LCDC bit 7 is clear. Otherwise it adds one dot per cycle. Dots `0–79` stay mode 2, dots `80–251` are mode 3 (pixel transfer), and dot `252` is mode 0 (HBlank). Call `renderScanline` on the cycle that enters mode 0, and call it once. The solid-tile fixture writes `0xFF` into `bus.vram[0]` through `bus.vram[15]` and `0` into `bus.vram[0x1800]`, then sets `lcdc = 0x91`, `bgp = 0xE4`, and `ly = 0`. `step(251)` leaves `framebuffer[0]` through `framebuffer[159]` at 0 and leaves `ly` at 0. `step(1)` on that same `Ppu` fills those 160 bytes with shade 3.
3. `renderScanline` walks `x` from 0 through 159 while LCDC bit 0 is set. For each `x`, compute `bgX = (scx + x) & 0xFF` and `bgY = (scy + ly) & 0xFF`, then `tileX = bgX >> 3`, `col = bgX & 7`, `tileY = bgY >> 3`, and `row = bgY & 7`. Read the map byte at `mapBase + tileY * 32 + tileX`. Bit 3 selects `mapBase`: `0` is `0x9800`, `1` is `0x9C00`. Bit 4 selects the tile address: `1` is `0x8000 + index * 16`, and `0` is `0x9000 + signedIndex * 16` where an index `>= 128` becomes `index - 256`. Read the two bytes at `tileAddr + row * 2` from the `Memory` passed to the constructor. Store `applyPalette(decodeTileRow(low, high)[col], bgp)` at `framebuffer[ly * 160 + x]`. The README pictures trace this loop for pixel `x = 0` of the solid fixture, for the map-byte row, and for the `SCX` and `SCY` shifts.
4. Two more fixtures use the same `step(252)` draw. Map index: `bus.vram[0]` through `bus.vram[15]` are `0x00`, `bus.vram[16]` through `bus.vram[31]` are `0xFF`, and `bus.vram[0x1800] = 1`. Pixels `0–7` are shade 3 and pixels `8–159` are shade 0. Scroll: tile 0’s first two bytes are `0x80, 0x80` and its other bytes are 0, so the row is `[3, 0, 0, 0, 0, 0, 0, 0]`. Tile 1 is sixteen `0xFF` bytes. Map row 0 stays tile 0. `bus.vram[0x1820]` through `bus.vram[0x183F]` are `1`. With `scx = 0` and `scy = 0`, pixel 0 is 3, pixel 1 is 0, and pixel 8 is 3. With `scx = 1` and `scy = 0`, pixel 0 is 0 and pixel 7 is 3. With `scx = 0` and `scy = 8`, all 160 pixels are 3. Each scroll pair needs a new `Ppu` so the dot counter starts at 0. The same pictures in the README show these rows.
5. Run `npm run test:lesson -- 14`. Edit `src/ppu/ppu.ts`. Leave the 456-dot line advance, VBlank, `STAT`, the window, sprites, and `doDma` for later lessons.
